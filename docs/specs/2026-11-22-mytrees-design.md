# 我的树 / 总管理 分层设计（2026-11-22）

## 意图 / 为什么

现在只有一层管理：`/admin/`，一个密码，进去能删所有人的树；而且定制页顶栏还挂着「⚙ 管理」入口，等于把总后台门牌挂在墙上。

要拆成两层：

- **总管理**：能看/删所有树。入口从前端彻底消失，只留一个不好猜的地址，仍用 `ADMIN_KEY` 密码。
- **我的树**：普通用户不输密码就能看到、删除自己造过的树。

## 目标

1. 用户零输入进入「我的树」，只看到自己的树。
2. 用户能删自己的树，且 **3 分钟内可以撤销**。
3. 总管理入口不在任何前端页面出现。
4. 用户换设备后仍有办法找回自己的树。

## 非目标 / 反目标

- 不做账号系统（不注册、不收手机号/邮箱）——这会毁掉「零输入」。
- 不引第三方二维码**服务**（需要联网、把链接发给别人）——改为本地内置二维码库，见「二维码」。
- 不做真正的定时清理任务（免费计划没有 cron）；改用「懒清理」。
- 反目标：用户的令牌只存在前端，绝不允许「知道 id 就能删」——删除必须服务端校验。

## 约束

- Netlify Functions + Netlify Blobs（无数据库、无 cron）。
- 免费额度敏感：索引 `index` 已存在（含 id/title/photoCount/createdAt/thumb），继续复用。
- 现有路由：`/api/create`、`/tree/api/photos`、`/api/admin`。

## 方案对比

| 方案 | 体验 | 代价 |
|---|---|---|
| A. 设备令牌（localStorage 存随机 token） | 打开即见，零输入 | 换手机/清缓存即丢 |
| B. 管理链接（token 写在 URL，用户自存） | 换设备可用 | 用户必须保存；链接泄露 = 可删 |
| **C. A+B 合体（选定）** | 平时零输入；换设备有救 | 多一个「保存管理链接」入口 |

选 C：目标用户是手机点开链接来的人，清缓存/换机极常见，只做 A 会持续有人问「我的树呢」。

**误删保护**：用户选 **3 分钟可撤销**。

## 设计

### 1. 身份：ownerToken

- `/api/create` 每次生成 32 位十六进制 `ownerToken`，写进树记录。
- 返回给前端：`{id, url, ownerToken}`。
- 索引条目里只存 **sha256(token) 前 16 位**（字段 `oth`），不存明文 token——索引是共享的，明文会泄露他人令牌。

### 2. 前端存 token

- 创建成功 → `localStorage["studio_my_trees"]` 追加 `{id, title, token, createdAt}`（新条目在最前，最多留 200 条）。
- 发布成功界面加两个动作：**「查看/管理我的树」**（跳 `/my/`）、**「我的管理链接」**（弹出面板：复制按钮 + **二维码**，提示「存到备忘录/收藏/微信收藏，换手机用它找回」）。

### 2.1 二维码（本地生成，离线）

- 用 vendored 的小库（`qrcode-generator` 之类，纯 JS，约 15–25KB），放 `studio/public/vendor/qrcode.min.js`，随站点一起部署，**不联网、不渲染到第三方**。
- 只在用户点开「我的管理链接」面板时按需生成一张 256×256 的 canvas（内容 = 完整 `/my/?t=...` 链接），不影响首屏。
- 提供「长按/右键保存图片」，方便电脑上生成、手机存下来。
- 如果实现时发现该库与现有 `build.js` 注入流程冲突，退化为只给复制按钮 + 明文链接（功能不丢）。

### 3. 「我的树」页 `/my/`

- 取 token 顺序：`?t=` 参数 →（写入 localStorage 后）→ localStorage。
- 两者都空：显示「本机还没有作品 + 去制作」。
- 列表项：缩略图、题字、张数、时间、**打开**、**删除**（擦除即入回收站，3 分钟内显示「撤销」）。
- 请求 `GET/POST /api/my`，头 `x-owner-token: <token>`。

### 4. 接口 `functions/my.js`

| 动作 | 说明 |
|---|---|
| `GET` | 按 token 的 sha 前缀过滤索引，返回自己的树（含 `deletedAt`） |
| `POST {action:"delete", id}` | 校验该 id 的 `oth` 与 token 匹配 → 记录搬到 `trash/{id}`，索引条目标 `del:Date.now()`，旧键删除 |
| `POST {action:"restore", id}` | 匹配 + `now-del < 3 分钟` → 从 `trash/{id}` 搬回、清 `del`；超时返回 410 Gone |
| 懒清理 | 任何人调 `GET`（my/admin）时，顺手删掉 `del` 超过 3 分钟的 `trash/{id}` 与索引条目 |

- 被标记 `del` 的树：`/tree/api/photos` 与 `/tree/?id=` 一律视为不存在（照片为空、题字不显示）。
- token 不匹配一律 404（不区分「不存在」和「不是你的」）。

### 5. 总管理处：隐藏路径 `/aokorin/`

- `studio/public/admin/` → `studio/public/aokorin/`（路径不出现在任何前端页面）。
- 定制页顶栏的 **「⚙ 管理」按钮删除**（只保留「手势实验室」和「站长 GitHub」）。
- 鉴权不变：`ADMIN_KEY`（`?k=` 或 `x-admin-key`）。
- 总管理额外能力：查看每棵树属于哪个 token（显示 `oth` 前 4 位）、**硬删除**（立即清空，不进回收站）。

### 6. 兼容

- `netlify.toml` 增加 `/api/my` → `/.netlify/functions/my` 的 200 重写。
- 旧树（没有 `ownerToken` 的）在「我的树」里看不到，但仍可被总管理看到/删除。
- 旧路径 `/admin/` 保留一个空的 404 页面（不重定向），避免旧链接暴露新路径。

## 留给实现者

- 回收站的 3 分钟按服务器时间算，是本设计的选择（不追求跨设备时钟一致）。
- 索引条目上限 500 条（沿用现状），超出后最旧条目不再出现在「我的树」。
- 界面文案与已有的深色玻璃风格保持一致（复用 studio 页样式）。
